1. How the program is distributed
---------------------------------

  - As source code (https://github.com/lorenzzhao/abfindungsoptimierer and the source archive
    abfindungsoptimierer-<version>-source.tar.gz on each release page). It does NOT contain the third-party
    components: pip installs them separately from PyPI, each with its own license files.

  - As standalone programs for Linux (AppImage, tar.gz) and for Windows (installer,
    portable ZIP), built with PyInstaller. These DO contain the components of
    sections 2 and 3 and follow section 5. Every package has a "licenses" folder with all
    license texts and notices, an exact version list (VERSIONS.txt) and the source code
    locations (SOURCES.txt).

All licenses listed below are compatible with the GPL-3.0-or-later.

3. Additional components of the standalone programs
---------------------------------------------------

Python (python-build-standalone)
  The programs contain the Python interpreter (Python Software Foundation License 2.0)
  in the build of https://github.com/astral-sh/python-build-standalone. It contains
  libraries such as OpenSSL 3 (Apache-2.0), SQLite (public domain), libffi (MIT),
  libedit (BSD-3-Clause), ncurses (MIT/X11), xz/liblzma (0BSD), bzip2, zlib, expat (MIT),
  mpdecimal (BSD-2-Clause) and libuuid (BSD-3-Clause); licenses/python/ holds the license
  texts of exactly those built into the bundled interpreter and modules, the list of code
  incorporated in CPython itself (CPython-<version>-incorporated-software.txt), the HACL*
  license (MIT) and the Unicode License of the unicodedata module.

PyInstaller
  The program launchers (abfindungsoptimierer, abfindungsoptimierer-cli) are PyInstaller's
  bootloader: GPL-2.0-or-later with an exception that allows distributing it with
  programs under any license; see licenses/pyinstaller/.

Linux system libraries (Linux packages only)
  A few libraries that not every Linux system provides are taken from the build system
  (AlmaLinux 8), for example the XCB utility libraries and libxkbcommon. The build allows
  only permissively licensed system libraries; licenses/system-libraries/
  SYSTEM_LIBRARIES.txt lists each one with package, version, license and source package,
  and the folder holds their license files. Libraries every Linux desktop provides
  (glibc, the C++ runtime, GLib, X11, Wayland, OpenGL, fontconfig, FreeType, D-Bus, zlib)
  are not included; the program uses the system's copies.

Microsoft Visual C++ runtime (Windows packages only)
  vcruntime140*.dll, msvcp140*.dll and concrt140.dll: Microsoft Distributable Code,
  redistributed together with the program under Microsoft's license terms; see
  licenses/microsoft/. They are the compiler runtime of the Microsoft C++ compiler that built
  the Windows binaries of Python, Qt, NumPy and the other components and count as System
  Libraries in the sense of the GPL-3.0 (section 1).

AppImage runtime (Linux AppImage only)
  The AppImage file starts with the AppImage type 2 runtime (MIT,
  https://github.com/AppImage/type2-runtime), which statically contains libfuse 3.15
  (LGPL-2.1), squashfuse (BSD-2-Clause), zstd (BSD-3-Clause), zlib (Zlib),
  mimalloc (MIT) and musl libc (MIT); see licenses/appimage-runtime/.

Inno Setup (Windows installer only)
  The installer is made with Inno Setup (Inno Setup License, permissive). Its setup
  program only installs and uninstalls this program.

5. How the license conditions of the standalone programs are met
-------------------------------------------------------------------

GPL-3.0 (the program itself)
  - licenses/LICENSE contains the license; the About dialog (Hilfe → Über …) and
    --version show the copyright, the license, the warranty disclaimer and where the
    source code is; "Lizenzen …" in the About dialog shows every license text.
  - The complete corresponding source code, including the build scripts in packaging/, is
    the archive abfindungsoptimierer-<version>-source.tar.gz (the same state as the Git tag
    v<version>). It is produced by the same build as the packages and offered for download
    on the same release page as the packages (https://github.com/lorenzzhao/abfindungsoptimierer/releases), which is equivalent
    access to the source code from the same place (GPL-3.0, section 6d).

LGPL-3.0 (Qt and Qt for Python) and LGPL-2.1 (libfuse in the AppImage runtime)
  - licenses/ contains the LGPL-3.0 and the GPL-3.0 it builds on; the AppImage also
    contains the LGPL-2.1 (licenses/appimage-runtime/).
  - The About dialog shows Qt's copyright notice and links both licenses.
  - The programs are built in folder mode, so the Qt libraries are ordinary files in the
    _internal/PySide6 folder and can be replaced with modified versions. The AppImage
    runtime can be rebuilt with a modified libfuse from its source code.
  - The unchanged source code of exactly the bundled versions of Qt (qtbase, qtsvg,
    qtwayland), Qt for Python (pyside-setup), the AppImage runtime and libfuse is
    downloaded by the build into release/sources/ and attached to the same release page
    as the packages (LGPL-3.0 section 4d / GPL-3.0 section 6d; LGPL-2.1 section 6);
    licenses/SOURCES.txt lists the archives with their checksums. The versions
    are pinned in packaging/pins.json and packaging/release-constraints.txt.

LGPL-2.1 (libiconv in lxml, libquadmath in NumPy on Linux) and the GCC runtime in NumPy
(libgfortran, GPL-3.0-or-later WITH GCC-exception-3.1)
  - licenses/LGPL-2.1.txt and the license texts in licenses/packages/numpy/ and
    licenses/packages/lxml/ (with a NOTE.txt each).
  - On Linux, libquadmath and libgfortran are separate shared libraries in numpy.libs and can
    be replaced. On Windows, libgfortran is part of numpy.libs\libscipy_openblas64_*.dll
    (GCC 10.3.0); that DLL is a separate file and can be replaced by a modified build. The
    GCC Runtime Library Exception allows the combination with this program. libiconv is linked statically into lxml; lxml's complete source code
    (buildlibxml.py builds it with its static libraries) is offered with the packages,
    so lxml can be rebuilt with a modified libiconv and replace the lxml folder.
  - The source code of exactly these versions – lxml 6.1.3, GNU libiconv 1.18 and the
    AlmaLinux 8 source package gcc-8.5.0-28.el8_10.alma.1 (Linux) and GCC 10.3.0
    gcc-10.3.0.tar.xz (Windows) – is downloaded by the build into release/sources/ and
    attached to the release page with the packages (pinned with their checksums in
    packaging/pins.json).

Notices of permissive licenses (MIT, BSD, Apache-2.0, PSF, Matplotlib, HPND, Unicode,
zlib, FreeType and others)
  - The license texts and copyright notices of every bundled component are in licenses/.
    The build (packaging/collect_licenses.py) assembles them and stops if any binary in a
    package cannot be assigned to a component with a known license, or if a Linux system
    library is under a GPL-family license.
